# Projects and pagination

Mode: Experience for the project gallery/detail; Read for the existing blog listing.

THESIS: Let visitors browse a manageable selection, then inspect a project's complete Markdown narrative and available images.

OWN-WORLD: Inherit the existing white/black/purple/cyan system, Manrope, sparse rules, rectangular imagery, compact black identity, and 16px text floor. No replacement identity or new raster assets.

STORY: Filter a discipline, move through project pages, open an existing project URL, inspect its image sequence and prose, and continue to another project. Blog readers browse five articles per static page.

FIRST VIEWPORT: The portfolio hero stays intact. Its gallery has six cards in three columns above 1100px, six in two columns at tablet widths, and five in one column on mobile. A quiet pager follows the cards. Detail covers become native horizontally scrollable figures; additional controls appear when an entry has multiple images.

INTERACTION: Project filters reset to page one. Pagination supports URL restoration and browser history, and resize keeps the first visible item's new page. Slider buttons, native touch scrolling, and arrow/Home/End keys select images without autoplay. Blog page links work without JavaScript. Without JavaScript all project links remain visible.

FINISH: Preserve all seven project slugs and copy. Verify desktop/tablet/mobile counts, pagination boundaries/filter reset/history/resize, two-image controls and no-JavaScript blog pagination using isolated fixtures, and existing portfolio/blog flows. Each original project currently supplies one image; no extra client material or fabricated project images are added.

SEED: Not applicable; this is a specifically requested extension of existing surfaces and mechanisms.
